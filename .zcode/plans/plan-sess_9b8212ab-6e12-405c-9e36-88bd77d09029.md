# 移植花笺的 Markdown 渲染（便签卡片只读渲染层）

## 模式：花笺「磁贴」模型的移植

- **卡片 = 渲染后的 Markdown 视图**（对应花笺 `tileRenderMarkdown`）
- **双击卡片 → 大编辑窗编辑 Markdown 源码**（对应 `tileDoubleClickToEdit` → 编辑面），弹窗仍是纯 textarea——"编辑的时候无所谓"
- 保存并关闭 → 卡片重新渲染 → **"最后保存能看 md 格式"**

### 交互变化（请知悉）
- 卡片上的**内联直接打字（P5 的 textarea）移除**，编辑统一走双击弹窗。理由：你说编辑无所谓；这正是花笺磁贴的做法；且单一数据源（弹窗是唯一编辑面）让 `n.content` 恒新鲜，上次"点开无内容"那类快照不同步 bug 的土壤整个消失。
- 空便签卡片显示「双击开始编辑…」占位；改名（点标题）、删除、新建均不变。
- 若之后想保留内联编辑，可再加"单击切编辑、失焦渲染"模式，约 30 行，不影响本次结构。

## 渲染管道（花笺管道的 vanilla 等价物）

| 花笺 | 我们 |
|---|---|
| react-markdown + remark-gfm | **marked 18.0.11**（GFM 内置：表格/任务列表/删除线/代码块）+ `breaks: true`（单换行→`<br>`，符合便签短行习惯，否则两行字会挤成一行） |
| rehype-sanitize | **DOMPurify 3.4.14** |
| KaTeX 数学、GitHub alerts | 不做（未被要求） |

消毒不是过度设计：页面持有 bridge 权限（`openPath` 等），从网页复制粘贴进便签的内容若含恶意 HTML，不消毒就会在 `app.local` 上下文里执行。

## 文件改动

1. **新增** `wwwroot/vendor/marked.min.js` + `purify.min.js`——jsdelivr 固定版本下载，共约 60KB，进 git，csproj 的 `wwwroot\**` 通配自动复制。吸取 Vditor 525 个文件的教训：这次就两个文件、零运行时外部依赖。
2. **index.html**：`app.js` 之前加两个 `<script>` 标签。
3. **app.js**：
   - 新增 `renderMarkdown(text)`：空文本 → 占位；否则 `DOMPurify.sanitize(marked.parse(text))`
   - `buildNoteCard`：textarea 换成 `<div class="note-md">`；`box` 的 dblclick → `openMdEditor(n)`
   - `openMdEditor(n)`：直接读 `n.content`（弹窗是唯一编辑面，恒新鲜）
   - `closeMdEditor`：保存后 `n.content = content` + `renderNoteWall()` 刷新卡片
   - **删除**随之失去意义的：`saveTimers` / `dirtyNotes` / `flushNotes` / `flushNoteOne`、600ms 防抖、失焦落盘（内联编辑没了，这些定时器逻辑全部退场）
4. **style.css**：`.note-md` 排版——便签黄主题、12px 紧凑字号，覆盖标题/列表/任务列表/行内代码/代码块/引用/表格/链接/图片/分隔线。
5. **C# 侧零改动**：存储仍是 `notes/*.txt`（内容即 Markdown 源码，扩展名不改，数据零迁移）；`NoteStore` / `MainForm` 不动。
